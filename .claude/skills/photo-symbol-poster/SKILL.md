# 照片 → 符号海报

一张照片进来，一张 2400×3200 的 PNG 出去：上半是照片本身，下半是从照片里萃取出来的一个抽象标识，像印在纸上的。

分工很明确：**符号由你来设计**（每张照片都不一样，这是这件事的全部价值），**裁切、调色、印刷质感、50/50 拼版交给脚本**（这部分每次都一样，没必要重写）。

## 流程

1. **看照片，写下三句话**（先想清楚再动手，符号好坏八成取决于这一步）
   - 主体是什么，它最不可替代的轮廓/结构是什么？
   - 画面里的关系是什么（谁落在谁上、谁朝向谁、哪里是清楚的哪里是虚的）？
   - 气质是什么（静、潮湿、锋利、失重……）？
   不确定主体是什么、或者画面有多个候选主体时，先问用户，不要猜。

2. **取色**：`python3 scripts/palette.py 照片 -k 9`
   聚类只能给出占面积大的颜色；面积小但最有识别度的颜色（一片落叶、一盏灯）通常聚不出来，需要你对着照片补上。油墨色可以在照片色相上适度提纯，但要在交付时说明哪些是照片原色、哪些是提纯后的。

3. **写符号 SVG**（规范见下），存成 `symbol.svg`。

4. **合成**：
   ```bash
   python3 scripts/compose.py --photo 照片 --symbol symbol.svg --out poster.png
   ```
   常用参数：`--focus 0.5,0.4`（裁切时主体所在位置）、`--fit extend`（见"上半区"）、`--grade 0..1.5`、`--misreg`、`--grain`、`--scan`、`--seed`。

5. **自己看一遍再交付**：缩略图看整体比重，再裁一块 1:1 细节看文字有没有压线、套印有没有错得太过。发现问题改 SVG 重跑，脚本几秒钟。

6. 交付时一并说明：符号里每个元素对应照片里的什么。用户要的是"能关联回原图"，这段说明就是检验。

## 上半区：照片

- 上半区是 3:2 横幅。脚本只做等比缩放 + 裁切，从不拉伸。
- 横图基本是直接铺满。竖图/方图默认 `cover` 裁切，用 `--focus` 把主体留在画面里。
- 裁切会切掉主体时才用 `--fit extend`：整张照片完整保留，两侧用照片自身的模糊延续填充。这**不是**生成式扩图，效果是"照片悬在自己的虚影里"，观感明显弱于真实延展——用之前告诉用户这个取舍，或者请他们提供横构图版本。
- 调色是克制的：轻微 S 曲线、抬一点黑位、降一点饱和、细颗粒。目标是独立出版物的印刷感，不是滤镜。用户要求原片不动就 `--grade 0`。

## 下半区：符号 SVG 规范

画布固定 `viewBox="0 0 2400 1600"`，根元素写 `data-paper="#EFEBE1"`（暖白/灰白纸色）。

**按油墨分版**：每种颜色一个顶层 `<g data-plate="名字">`，脚本会把每一版单独渲染，再按文档顺序用正片叠底一版一版"印"上去——叠印处自然变深，各版之间有几像素的错位，这就是印刷感的来源。所以：
- 一版只用一个颜色。浅色版在前，深色版在后。
- 黑/深色的线稿与文字放在最后一版，加 `data-register="key"`（基准版，不偏移），其余各版相对它错位。
- 想要"露白"用 `<mask>` 从色块里挖，不要盖一块纸色（盖上去的纸色在叠印里是不存在的）。
- 在同一位置给每一版都画一个小套准十字，错位才会被看见。

结构可以直接从 `examples/moss-mound/symbol.svg` 起手，那是一个完整的、跑通过的例子（苔藓石丘 + 落叶）。看结构，别抄造型。

### 怎么提炼符号

目标是一个**标识**，不是插画，也不是信息图。检验标准：把下半区所有小字遮掉，剩下的图形是否仍是一个完整的、能被记住的形；再把上半区遮掉，告诉别人"这是从一张苔藓照片来的"，对方是否会说"哦，对"。

- **一个主形 + 一到两个附属形**就够了。主形来自主体最大的轮廓（丘 → 弓形，塔 → 竖条，人 → 倾斜的轴），附属形来自最有识别度的细节（七裂的叶 → 七瓣扇形）。
- **把摄影语言也翻译成图形**，这通常是符号里最聪明的部分：焦平面 → 一道贯穿的细缝；景深衰减 → 逐渐变宽的条纹；虚化背景 → 一个平涂的圆；运动 → 一段弧形轨迹加节点。
- **负空间**：照片里的浅色物体优先用挖空表现，而不是再加一个颜色。
- **构造线**是系统感的来源：把主形所属的完整圆用虚线补出来、画出基线、轴线、法线、夹角。它们必须是真的——角度、半径的标注要和图形的实际几何一致，自己算出来再写，不要编一个好看的数。
- **秩序 × 误差**：几何是精确的，误差来自印刷（错位、颗粒、掉墨），不要靠手抖的线条去假装。
- 符号整体居中或略偏，占画布宽度的 40–55%，四周留白。宁可少一个元素。

### 颜色

3–4 个专色 + 一个深色基准色，全部写进符号系统里：
- 主色：照片里面积最大、最有代表性的那个色。
- 一到两个辅色：识别度最高的小面积色、环境色。
- 一个**信号色**（洋红/橙/青蓝等照片里没有的颜色）只用于功能编码——一个索引三角、一个节点、一个编号——面积控制在极小。它是系统标记，不是装饰。
- 深色基准色用照片里最暗的颜色，不要纯黑。

### 文字

文字是系统的零件，没有标题。等宽字体（`'JetBrains Mono', 'DejaVu Sans Mono', monospace`），22px 左右，字距 0.09em，次要信息降到 60% 不透明度。可以放的内容：
- 来源索引（原文件名 → SIGN）、图号。
- 元素编号与名称（01 MOUND / 02 LEAF ×7），紧挨对应的图形。
- 色彩编码（色块 + 代号 + 色值）。
- 至多一句很短的话。

**只写真的东西**：文件名、能从图形量出来的数值、实际用到的色值。相机型号、光圈、地点、日期这些，只有在 EXIF 里读得到或用户告诉你时才写；读不到就不写，不要为了"档案感"编造。

## 环境

需要 Python（Pillow、numpy）和 Node 的 `playwright`（用 Chromium 渲染 SVG 分版）。没有 JetBrains Mono 时会回退到系统等宽字体。输出默认 2400×3200，`--width` 可改（会保持 3:4 且上下严格对半）。
